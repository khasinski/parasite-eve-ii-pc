# PE2 Save Editor (`save-editor/`)

Save editor for Parasite Eve II (PS1 / PC PsyZ port), modeled after the PE1
editor in `~/Projects/parasite-eve-pc/save-editor`: an egui GUI plus a clap
CLI over one shared save model.

## Save format

The format is taken directly from the decompilation (`src/main/mc.c`,
`include/main/mc_types.h`). One card file is one 8 KB block named `BASLUS-01042` + a slot letter (`A..O`, the
directory index) + seven random characters the game picks when it creates the file (20 characters in all):

| Section | Offset | Copy size | Extent | Contents |
| --- | --- | --- | --- | --- |
| 0 header | 0x0000 | 0x200 | 0x200 | Card file header ('S','C', Shift-JIS title, CLUT, icons); no checksum |
| 1 save | 0x0200 | 0x944 | 0x1300 | `McSaveData` live copy + backup |
| 2 player | 0x1500 | 0x040 | 0x0080 | `PlayerStatus::save` + backup |
| 3..7 flags | 0x1580.. | bank | banks ×2 | Per-stage game-flag banks, live + backup |
| 8 nibble | 0x1C00 | 0x100 | 0x0200 | `GameFlagNibbleBank` live + backup |

Checksums (all low-16-bit, stored with ones' complement `0xFFFF - sum`):

- every checksummed record: signed-byte sum of its payload (`(s8)byte`)
- `headerChecksum`: signed-byte sum of the 56 bytes from `location`, with the
  pair itself pre-set to `0` / `0xFFFF` before summing (contribution -2)
- `titleChecksum`: signed-byte sum of the 0x200-byte card file header
- `bufferChecksum`: unsigned low-byte sum of the live sections' checksums;
  its pair is zeroed before section checksums are written, and written last

`SlotData::refresh_checksums` replicates the game's write order exactly:
title pair → header pair → zeroed buffer pair → section checksums → summary.

## Layout

- `src/layout.rs` — section table and file offsets
- `src/checksum.rs` — the four checksum algorithms and verifiers
- `src/save.rs` — typed `SaveImage` over the 0x944-byte record with offset
  accessors; `SaveTransfer` for lossless JSON round-trips of typed fields
- `src/card.rs` — containers: PsyZ directory, raw 0x2000 file, `.mcs`,
  `.srm`/`.mcr`/`.mcd`, DexDrive `.gme`
- `src/edit.rs` — `SlotData`: whole-file edits + checksum maintenance/verify
- `src/names/` — id → name tables (items, key items, stages, areas, PE slots,
  game modes, nibble flags, stage-bank object slots); `item_names.rs` and
  `decomp_names.rs` are generated by `tools/gen_item_names.py` and
  `tools/gen_decomp_names.py`
- `src/cli.rs` — CLI: `list`, `inspect [--flags]`, `items`, `verify`, `edit`,
  `export`, `import`, `extract`
- `src/gui.rs` — egui app: slot browser, tabs (Summary, Character,
  Inventory, Key Items, Weapons, Parasite Energy, Progression, Game Flags, Options)

Unknown bytes are never modeled or rewritten: edits go through the typed
accessors, JSON transfer carries only typed fields, and both operate on the
raw image so everything else is preserved verbatim.

## What the editor names, and where it comes from

| What | Stored in | Decoded as | Source |
| --- | --- | --- | --- |
| Item names | item rows, weapon loads | `names::ITEM_NAMES` (short names only) | catalog behind `gItemDescriptors`/`gItemKeyDescriptors` (`src/gameplay/item_catalog.c`), decoded from the disc by `tools/peassets` into the uncommitted `assets/<region>/inventory/` |
| Item categories | id ranges + catalog class | `ItemCategory` | `include/gameplay/items.h:371-390` (0..0xBF ordinary: <0x60 items, 0x60 armour, 0x80 weapons, 0xA0 ammo; 0x100..0x17F key items), `include/gameplay/inventory.h:105-139` (`classification`, `ITEM_SUBTYPE_MEDICINE`) |
| Inventory rows | `itemRows[0x100]`, window `carriedItems` | name, category, qty, rounds loaded, armour slot | `include/main/mc_types.h:10-95` |
| Key items | `collectedBits` bit = id & 0x7F | held / not held | `inventoryGetItemQuantity`, `INVENTORY_COLLECTION_ID_*` (`include/gameplay/items.h:190-261`); giving the Ice Bag restarts its timer like `inventorySetCollectedBit` (`src/gameplay/item_boost.c:819`) |
| Equipped weapon / ammo / armour, HP/MP | `PlayerStatus` bytes 0x21/0x22/0x23, 0x18..0x1F | item ids (stored as id-0x7F, id-0x9F, id-0x5F) | `include/main/wipsys_types.h:76-100` |
| Weapon loads | `weaponItems[0x20]` | weapon name, primary/secondary ammo names (0xFF unavailable) | `include/main/mc_types.h:37-63` |
| Parasite Energy | `attachLevels[i]` | slot i = catalog item 0x0F + 3i (Pyrokinesis..Energyball); 12..17 unused | `src/gameplay/item_panels.c:1177` |
| Location | `GameLocationKey` | stage + area name | `include/main/session_types.h:21-44`, `include/main/areas.h` |
| Mode | `gameMode`, `clearCount` | Normal (0, no clears) / Replay / Bounty / Scavenger / Nightmare | `include/main/mc_types.h:139` |
| Stages visited | `visitFlags` bits 1..5 | stage names | `include/main/mc_types.h:140`, `src/gameplay/companion_load.c:463` |
| Stage banks | sections 3..7 | visited areas (bit area-1), 64 two-bit object states (inactive / available / taken / replenishable), area placement records | `include/main/gameflag_types.h:57-228`; object-slot names from `src/mapui/map_shelter/map_shelter.c:533` and `src/mapui/map_neo_ark/map_neo_ark.c:151` |
| Nibble bank | section 8 | 504 four-bit flags (even index = high nibble); named flags, story chapter, objective; play-time mark at payload 0x34 (positions 0x68..0x6B) | `include/main/gameflag_types.h:34-56`, `include/main/event_flags.h`, named entries of `include/main/gameflag_ids.h` |

Still unknown and shown raw: `GAME_FLAG_<HHH>` placeholder flags and unlisted nibble positions,
object slots of Akropolis and Dryfield (no slot enum yet), area-record trailing bytes, unnamed
collection bits (0x10D/0x10E/0x126/0x129..0x12B and other event bits), `unknown_*` save bytes,
per-weapon accepted ammunition and stack limits (catalog data, not in source). Equipping armour
is display-only: the game recomputes HP/MP and detaches attachments when armour changes.

Regenerating the tables (from the repository root):

```sh
python3 -I save-editor/tools/gen_decomp_names.py . save-editor/src/names/decomp_names.rs
python3 -I save-editor/tools/gen_item_names.py assets/USA save-editor/src/names/item_names.rs
```

## Usage

```sh
cargo run -- list ~/Library/Application\ Support/parasite-eve-ii-port/parasite-eve-ii/card0
cargo run -- verify card0 --slot 2
cargo run -- edit card0 --slot 2 --set exp=99999 --set mark-items-seen=384
cargo run -- inspect card0 --slot 2 --flags      # names, inventory, key items, flag banks
cargo run -- items --category weapon             # the item catalog
cargo run -- edit card0 --slot 2 --add-item "9mm Hydra:50" --add-key-item "Red Key" \
    --equip "M93R:9mm P.B." --set-flag 0x7A=1
cargo run -- export card0 --slot 2 -o slot2.json
cargo run -- import card0 --slot 2 -i slot2.json
cargo run            # GUI
```

## Verification

`cargo test` covers layout chaining, checksum round-trips, edit + verify,
corruption detection, transfer round-trips, the name tables, inventory/key-item/
equipment/flag-bank decoding and edits, every GUI tab rendered headless, and the
CLI's named edits end to end. Save files are never
rewritten in place without a fresh checksum refresh.

## Containers and file names

The port stores each card as a directory of unmodified save files (`card0/`, `card1/` under the per-user data
directory, or under `PE2_MEMORY_CARD_DIR`). The editor edits a file in place under its own name, never renames or adds
a second file, and only creates a name (`BASLUS-01042<letter>0000000`) for a slot that has none. Raw card images are
read through the card's own directory (frames 1..15, in-use marker 0x51) and a slot is overwritten only where that
directory already lists a PE2 save for it.

Not verified against a retail save: the layout was derived from the decompilation and the offsets of every typed field
were compared with `offsetof(McSaveState, ...)` from `include/main/mc_types.h`; the checksum order follows `mc.c`. Try
it on a copy of a real save and load the result in the game before trusting it. The name decoding was checked against
saves written by the port (an early Akropolis save decodes as Akropolis Square, Leather Jacket equipped, M93R with 20 of
its 100 9mm P.B. loaded, MIST Badge held, story chapter Akropolis); edits of such a copy change only the targeted bytes
and their checksums.
